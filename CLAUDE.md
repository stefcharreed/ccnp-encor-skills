# CLAUDE.md — ccnp-encor-skills

Public CCNP study skill catalogs. Repo: https://github.com/stefcharreed/ccnp-encor-skills (public).

**Two catalogs live here** (as of 2026-09-28):
- **ENCOR 350-401** — `1.0.0/skills/`. **Complete**: all six blueprint domains, 32 topic
  skills, OCG Chapters 1–29 captured. Generated by `ccnp-encor:ccnp-note`.
- **ENARSI 300-410** — `1.0.0/skills-enarsi/`. **In progress**, started 2026-09-28.
  Generated by `ccnp-encor:enarsi-note`.

The plugin is still named `ccnp-encor` and both directories are declared in the
`pi.skills` array in `1.0.0/package.json`. **The name is a deliberate misnomer** — renaming
it would break `ccnp-encor@local` in `~/.claude/settings.json`, the public repo URL, and the
slash commands. Do not rename it without being asked.

`enarsi-note` does **not** restate the skill template. It reads `ccnp-note` and applies four
substitutions. **`ccnp-note` is the single source of truth for the template** — change it
there, not in two places.

## What this is
Phase 1 (this repo, public): collecting CCNP topics as individual
Claude Code skills under `1.0.0/skills/<topic>/SKILL.md` (ENCOR) and
`1.0.0/skills-enarsi/<topic>/SKILL.md` (ENARSI). Each skill is
generated by the relevant note plugin skill from study notes (raw
notes, IOS-XE config, `show` output, or spoken description).

Phase 2 (separate private repo,
[network-troubleshooting-agent](https://github.com/stefcharreed/network-troubleshooting-agent),
**planning underway, no agent code written yet**): combine the topic skills
from this catalog into a single agent capable of diagnosing real network
problems across multiple topic areas, not just one isolated skill at a time.
That repo already has architecture notes (retrieval-not-reasoning design,
a worked InterfaceDown+config-drift correlation example) and is gated on this
catalog reaching Tier 1 coverage first — see its `ARCHITECTURE-NOTES.md` for
the current tiering (FHRP, DHCP, NAT, ACLs, first-hop security, AAA next;
SNMP/syslog/NetFlow/IP SLA after that; QoS/Wireless/Automation/Architecture
deferred). Kept in a separate private repo since it will likely involve real
device interaction patterns. The public README teases this with a CTA to
reach out via LinkedIn — do not start phase 2 *implementation* work in this
repo, and do not restructure this repo's layout for portability unless
explicitly asked.

## Layout
- `1.0.0/skills/<TOPIC>/SKILL.md` — one file per ENCOR topic
- `1.0.0/skills-enarsi/<TOPIC>/SKILL.md` — one file per ENARSI topic
- `1.0.0/skills/ccnp-note/SKILL.md` — generates ENCOR skills (template source of truth)
- `1.0.0/skills-enarsi/enarsi-note/SKILL.md` — generates ENARSI skills (reuses that template)
- `1.0.0/package.json` — plugin manifest
- `1.0.0/.in_use/` — runtime PID lock file, gitignored, never commit

## Where this repo lives (2026-09-29)
The working copy is `~/git/ccnp-encor-skills`, and it is also the `local` marketplace
(`claude plugin marketplace add ~/git/ccnp-encor-skills`). Claude Code loads a **copy**
of it from `~/.claude/plugins/cache/local/ccnp-encor/<commit>/` — that cache is
disposable and gets rebuilt, which is why a repo kept inside it kept losing `.git`.
Never edit or commit in the cache. After pushing, run
`claude plugin update ccnp-encor@local` (or restart) so the loaded skills pick it up.
`.claude-plugin/marketplace.json` exists only locally (listed in `.git/info/exclude`).

## Workflow rule — always push after adding a skill
**Every time a new topic skill is written or an existing one is edited,
commit and push immediately.** Do not leave new skills uncommitted.

```bash
cd ~/git/ccnp-encor-skills
git add -A
git commit -m "Add <topic> skill"   # or "Update <topic> skill"
git push
```

This applies whether the skill was created via `/ccnp-note <topic>` or
edited directly. No need to ask for confirmation before this push — it's a
private repo dedicated to this catalog, committing/pushing study notes here
is pre-authorized.

## Safety
- This repo is public — do not commit anything that shouldn't be public
  (real device state, credentials, personal info beyond what's already in
  the README). Phase 2 (device interaction, lab details) belongs in the
  private `network-troubleshooting-agent` repo instead.
- Never commit `.in_use/` or other runtime state.
